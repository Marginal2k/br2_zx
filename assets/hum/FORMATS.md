# Куски образа v0.04 в `assets/hum` (INCBIN в `src/game`)

Это байты выпущенной v0.04 (людей), для которых в архиве автора нет файла. Имя файла: `<страница>_r<число>_<адрес>.bin` или имя метки; адреса - в образе v0.04.
Всё, что оказалось **кодом**, разобрано в исходник (в `assets` не лежит): `IXA3_0` (101 байт `#D8E0`, `lih.asm`), `DEFENC` (100 байт - таблица параметров, а не код: `var.asm`, `DEFB`).
Остальное - данные; формат (насколько он известен по коду, который их читает):

| Файл | Байт | Где | Что |
|---|---|---|---|
| `M_r6161_8000.bin` | 4096 | `level.asm`, `MAP #8000` | карта уровня людей (версия v0.04 `4_10.MAP`, совпадает на 99,8 %): 64x64 клетки по 1 байту (номер тайла/объекта), `setMAP` строит по ней `MAP2`; **бит 7 клетки = туман** (`onsee` сбрасывает его вокруг юнита; в образе людей флагов нет) |

`assets/kun/*` - то же для кунгов: в сборку не входят (кунги работают на общем коде, см. `docs/NOTES.md` 10.2).

## Что установлено при портировании утилит автора (tools/gfx, tools/txt; подробно - docs/TOOLS.md)

Формат спрайтов из `4HERO.CPP`/`4MISC.CPP`: пары байт `(M, M^I)` (маска, маска XOR рисунок), столбцами (по 16 или 24 строки). Часть блоков образа v0.04 - того же формата:

| Файл | Раскладка в редактируемом листе | Основание |
|---|---|---|
| `hrh7`, `hrh8`, `hrm19`, `hrm20` (960) | тип 2 (15 кадров 2x2) | тот же размер; 668-682 из 960 байт совпадают с `4KAPELL/4KING/4VARLOK/4ZERG.DAT` |
| `4_r0_CD80` (2304) | тип 8 (16 кадров 3x3), как `4TANK_TR` | размер; совпадений в архиве нет |
| `4_r0_FA50` (432) | тип 7 (3 кадра 3x3) | равен `4MISC3X3.DAT[432:864]` |
| `6_r775_E88F` (288) | тип S (тень 3x2), первые 3 кадра | равен `4~SHADOW.DAT[0:288]` |
| `WM22` (2880) | раскладка `4MISC2X2`, 45 кадров (в архиве 46: 2944 байта) | лист общий с 4misc4x4/1x1/1x2 и WM33, конфликтов ячеек нет |
| `WM33` (1296) | раскладка `4MISC3X3` | тот же размер, содержимое новее архива |
| `WNAMES` (1890) | не текст, а графика: 45 названий по 42 байта (6 байт x 7 строк), как `4NAMES.DAT` (47 названий); раскладка `conv_names` из `4BAR_BUT.CPP`, в листе `4bar.png` | размер 45 x 42 |
| `3_r0_D270/D870/F770`, `4_r0_DA40` (576), `hrm18` (1616) | **геометрия неизвестна**: типы A..E появились после `4HERO.CPP`, порядок кадров автор нигде не описал. Показаны столбцами по 24 (576) или 16 (1616; 16 байт хвоста - в JSON) строк: сверху маска, под ней рисунок. Для правки годятся, как кадры - нет | это не раскладка автора |
| `TASK_M` (84) | задание: 4 строки по 20 знаков + байт 127 (формат `4TSKTXT2`), в кодах `4FONT.FNT` | читается `tools/txt/tasks.py`; `assets_src/text/task_m.txt` |
| `SOU6` (53) | 13 четвёрок + `#FF` | `assets_src/text/sou6.txt` |
| `datMIN` (512) | 16 байт параметров шахт + 124 записи по 4 байта (владелец, тип, x, y; владелец 255 - конец/заполнитель) | `assets_src/maps/hum_her.txt` |
| `M_r6161_8000` (4096) | карта 64x64, 1 байт на клетку | `assets_src/maps/hum_map.csv` |

Прочее, установленное сверкой с архивом: `.MAP` = 4096 (карта) + 257 байт хвоста, `.HER` = 496 байт = 124 записи по 4 байта; ч/б картинки (`4INSTR0`, `4INTRO`, `MAINFRAM`, 6144 байта) лежат в экранной раскладке Спектрума (TIF -> `6144.EXE`, у которого нет исходника), листы спрайтов (4LAND, 4HERO, 4MISC, кнопки, панель) - построчно, как в TIF; кадр TV16 - 28x36 точек, 16 градаций, 2 точки в байте, 504 байта, строки парами (`4TV16.CPP`).
