# Чёрный Ворон 2 (демо v0.04): устройство проекта (фаза 2b-2)

Исходники - `src/`, ресурсы - `assets/`, сборка - `python build.py` (см. README.md). База - замороженные деревья `work/src_v04/game`
(one tree: люди / кунги через `-DKUN`), `work/src_v04/start1`, `work/src_faithful/final`; здесь они переработаны в обычную игру на TR-DOS.
Старое (как было в v0.04) - `work/original_v004_src/` (перенесено из src/), в сборку не входит.

## 1. Что получилось (по решениям пользователя)

1. Одна игра: страницы 128K собираются один раз (`src/game/game.asm`), поведение - код v0.04 людей. Кунги - те же страницы + свои данные
   (ландшафт 44SPR, кнопки 4K_BUTT, карта 4_4.MAP + 4_4.HER, параметры COLOR #30, MASTER 1, fsLAND 4).
2. Стартовое меню (`src/game/menu.asm`, образец - меню ЧВ1): 1 Люди / 2 Кунги / 3 Загрузить (потом номер слота). Нет нажатий 30 с - демо.
   Демо (`demo.asm`) восстановлено по `__DEMO.A80`: случайный бой на уровне людей, любая клавиша - меню. Из игры в меню: победа
   (`LODnxt`), пункт "выход" меню паузы (`toMENU`).
3. Уровень читается с диска: `LODlev` (файлы `lev_h`, `lev_k`). Задание/картинка уровня: **в v0.04 их нет ни у людей, ни у кунгов**.
   `datSCR` (10240 байт) в образе людей - сплошное #50 (мусор ассемблера), `TASK_M` (84 байта) - не задание, а заставка
   "ЧЁРНЫЙ ВОРОН-2 / СЛУЖБА ... / GOLD SERIES / (C) 1998 COPPER FEET", одинаковая у обеих сторон; отладочный вход v0.04 `wMAIN` вообще не
   вызывает `LODlev` (который выводил картинку). Тексты `DOC\4TASKS.TXT`/`TASK\4_000.TSK`, `4_800.TSK` относятся к другим уровням
   (4_000 - "Камень бытия", 4_800 - "Безвыходная ситуация"); соответствия уровню 4_10 / 4_4 в данных нет. Поэтому ничего не показывается (как в v0.04).
4. Сохранение/загрузка починены (`io.asm`, `disk.asm`): слоты на диске игры, без шифрования, 8 слотов по 54 сектора. Меню паузы:
   пункты "заново" (`LODrtr`), "быстро сохранить" (`qSAVE`, слот 1), "быстро загрузить" (`qLOAD`), "выход" (`toMENU`); обычное сохранение - окно слотов (`M_M9`).
5. Защиты убраны (раздел 5). 6. Снег убран (раздел 4). 7. Диски - раздел 2. 8. B01 из BR2DISK1 (код из `start1`, данные новейшие), шрифт `DATA\4FONT.FNT`.

## 2. Диски

Обычный TR-DOS: сектора по 256 байт, логическая дорожка = цилиндр*2+сторона. Игра и загрузчики читают файлы **по положению** (таблицы строит `build.py`),
каталог TR-DOS служит для людей. Дисковый модуль один на программу: `src/game/disk.asm` (игра: `D_READ`, `D_WRITE`, `READ`, `SLOTPOS`) и
`src/start1/disk.asm` (загрузчик: `READ`, `POS`, `TR00`). Чтение - куски ПЗУ TR-DOS 5.03 через `#3D2F` (код игры лежит в `#4000..`, вход `#3D13` нельзя).

| Образ | Что |
|---|---|
| `br2_game.trd` (640 К, метка `BR2GAME`) | boot (BASIC) -> `br2` (загрузчик, 6 секторов на `#6000`) -> игра. Файлы: `g_pg0,1,7,6,3,4` (страницы, ZX0), `g_pg5a/b` (код страницы 5, две половины), `land4a/b`, `land5a/b` (ландшафты кунгов/людей, две половины), `butt_h`, `butt_k`, `bar`, `lev_h`, `lev_k`, `menu`, `saves` (8 слотов) |
| `br2_intro.trd` (640 К, `BR2INTRO`) | boot -> `br2` (загрузчик диска 1) -> заставка, меню диска 1 (1 ролик, 2 игра, 3 прощальное слово/инструкция, 5 "в духе времени"); файлы `title`, `intro` (B01), `f02..f05` (страницы LPZ), `final0/1`, `f16..f57` (ролики LPZ автора) |
| `br2_1mb.trd` (1 МБ, `BR2GAME`) | то же, одним диском: часть игры лежит **на тех же секторах**, что на диске игры, потом файлы диска 1 |

Пункт "Игра" диска 1 (`bGAME` в `loader.asm`): проверяет метку диска (`BR2GAME ` в системном секторе); нет - просит вставить диск игры
(текст шрифтом ПЗУ, ENTER - повторить). На 1 МБ метка совпадает, диск не меняется. Положение файлов игры (`game_layout.inc`) зашито в загрузчик диска 1.
Игра собрана один раз для всех образов: `RESTAB`, `SAVELIN`, `NSLOTS` (`disk_layout.inc`) одинаковы, `build.py` повторяет раскладку до сходимости
(длина упакованной страницы 5 зависит от `RESTAB`).

Упаковка: ZX0 (`tools/bin/zx0.exe`, декодер `src/lib/dzx0.asm`) - всё, что делали мы; LPZ автора (`xdelpz.asm`) оставлена для заставок, роликов и музыки
диска 1 (файлы взяты из архива как есть, `LP5` = страница tv16 упакована `tools/lpz.py`: она изменена из-за "снега").

## 3. Загрузка игры и карта памяти

Загрузчик (`src/start1/loader.asm`): страницы 1,7,6,3,4,0 читаются в буфер `#8000` (страница 2 пока свободна) и распаковываются в окно `#C000`;
код страницы 5 лежит двумя половинами (по 8 КБ), читается в `#6600` и распаковывается в страницу 2 (`#8000`, `#A000`); `STARTR` (`#FF00`, страница 0,
`src/game/starter.asm`) меняет страницы 5 и 2 местами и прыгает в `JP_ST`. `tools/check_loader.py` проверяет пересечения (ошибка = падение сборки не даёт, запускать вручную).

Страница 5 (`#4000-#7FFF`): код v0.04. **Перемещаема** (раздел 10.3): фиксированы только `#4000..#4040` (переменные, стек, вектор IM2 `JP INTRP` в `#4040`) и массивы героев `#7680..`
(`level.asm`). Где что лежит, видно из `build/game/main.sym`; порядок: переменные и стек, клавиатура/случайные числа, `LEVVARS` (переменные уровня, 268 байт) и за ними таблицы `TABS..TABSEND`
(не должны пересекать границу 256-байтовой страницы: код меняет только младший байт адреса; перед `LEVVARS` при необходимости вставляется выравнивающий пропуск), системные подпрограммы, `lib1a`, `intv`, `lid`,
дисковый слой и новые модули (`io`, `startm`, `demo`), шрифт `WFONT`, ZX0 (`dzx0`), `demo2`, `lib2`, `sound1`, `scan`, переменные (`local`, `var`).
Что отличается от v0.04 (удалено/заменено; прежние адреса v0.04 больше не действуют):

| Было в v0.04 | Стало |
|---|---|
| `JP_ST` | строит таблицу IM2 в странице 2, `LD I,IM2_I`, `IM 2` |
| проверка контрольной суммы денег (`chkCRC`, `suMdig`, `setCRC`) | удалена (в странице 0 остались заглушки `DEFS 3`: размер кода страницы 0 сохранён) |
| таблица IM2 `#4100` (257 байт `#40`) | `LEVVARS`: переменные уровня (`levvars.asm`), таблица IM2 - в странице 2 `#BA00` |
| `antiTM` | удалена |
| `LODrtr`, `LODnxt`, отладочный `wMAIN` | `startm.asm` |
| дисковый код 1997 года (`D_WRITE`, `READ`, `LOADms`, `ENCODE`, `DECODE`, `SAVgam`, `LODlev`, `CHNGd2`, `GSinsr`) | `io.asm` (+`disk.asm`), `startm.asm`, `demo.asm` |
| шрифт 912 байт `#5B3A` | шрифт `DATAFONT.FNT` (метка `WFONT`) |
| распаковщик LPZ (+ ловушка `PROTeC`) | ZX0 (`dzx0.asm`) и `demo2.asm` |
| `WBAR` (рисунок панели `4bar.dat`, `#7680..`) | панель читается с диска (`bar`) в `DSCR` перед `putBAR`; на `#7680` только массивы героев |
| мёртвая таблица `CALL_` за замыканием цикла игры, `JR INAMM` и дыры | убраны (`KUNFOG`, `NOPROC`, `LVTAIL`, `LDMPS` - новые) |

Страница 2 (`#8000-#BFFF`): `MAP #8000`, `MAP2 #9000`, `DSCR #A000` (рабочий экран, 6144), `BUF512 #B800`, **`IM2_TAB #BA00`** (257 байт `#40`), `MINE #BB40`,
`HBUILD`, `KBUILD`, пули (`KBUILD+256`) до `#BF90`. Массивы зданий не разрознять: номер здания 0..71 - подряд (`MINE`, `HBUILD`, `KBUILD`), код считает адрес по номеру.
Страница 0: код до `#FBAC`, `STARTR` на `#FF00`. Страницы 1,3,4,6,7 - как в v0.04 (ландшафт/кнопки читаются из файлов при смене стороны).

Файл уровня (`lev_h`, `lev_k`): три блока ZX0 в порядке MAP (`#8000`, 4096), `BUF512` (`#B800`, 512: 16 байт параметров шахт + `datHER`), переменные уровня (`LEVVARS`).
Кунги: образ v0.04 кунгов снят из работающего эмулятора (в `kun_live.txt` перечислено живое состояние), поэтому чистый старт собран из карты
`4_4.MAP` + `4_4.HER` (в `BUF512+16`) и параметров образа (COLOR `#30`, MASTER `1`, fsLAND `4`); `datMIN` (первые 16 байт `BUF512`) и остальное - как у людей.
`LODlev` обнуляет массивы зданий и пули, затем вызывает `mkIM2`. Люди: уровень из образа v0.04 (карта образа, на 99,8 % совпадает с `MAP\4_10.MAP`).

Старт игры (`startm.asm`): `wGAME`: `LODlev` -> `LDRES` (ландшафт `_sLAND`, кнопки `_sBUTT`, панель в `DSCR`) -> `putBAR` -> `SEEonn`, `setMAP` -> `_start`
(таблица вызовов v0.04, как есть). Цикл игры: в его начале вместо `LD SP,STKTOP` стоит `CALL NNNHK` (тот же размер): в демо-режиме он выходит в меню
по клавише и дирижирует боем (`d_LIFE`, `d_CTRL`, `d_NEW`).

## 4. Прерывания и "снег" (Sinclair 128K/+2)

Раньше: игра `I=#41` (таблица `#4100`, страница 5), интро/ролики `tvSTRT` `I=#70` (таблица `#7000`), концовка `FCstrt` `I=#70`. На фирменных 128K/+2 при `I` в `#40-#7F` ULA портит
изображение (нужна полная таблица из 257 одинаковых байт: на плавающей шине при подтверждении прерывания байт любой). Теперь таблица всегда в странице 2 (`#8000-#BFFF`, не сжимаемая):

* игра: `I=#BA`, `#BA00-#BB00` = `#40`, вектор `#4040` (`JP INTRP`; он там был и раньше);
* интро/ролики (`tv16.asm`): `I=#AA`, таблица `#AA00-#AB00` = `#71` в пустом промежутке перед музыкой, вектор `#7171` - обработчик;
* концовка (`final.asm`): `I=#8C`, `#8C00-#8D00` = `#71` в свободной подкладке `DEFS 44000-$`;
* при выходе в IM1/ПЗУ `I=#3F`: `F_CUT`, `bSTARS` (после роликов), `bGAME`, загрузчик.

Для игры место освободили так: переменные уровня (268 байт) перенесены в страницу 5 (в место таблицы и контрольной суммы), массивы зданий и пуль сдвинуты вверх на `#140`.
Проверено в эмуляторе: игра `ri` -> PC=`#4040`, `I=#BA`; ролик `I=#AA`; концовка `I=#8C`.

## 6. Отличия от v0.04 (кроме заказанных)

* кунги: **код один, различия по стороне - в рантайме** (раздел 10.2: данные уровня, `MPsign`, туман по `MASTER`); образ кунгов - снимок работающей игры, его живое состояние не переносилось;
* `NNNHK` и демо; панель рисуется из файла; `LODlev` вместо отладочного входа;
* `DEFR n` (случайный мусор ассемблера автора) везде нули;
* в `lih.asm`/`lid.asm`/`lib1a.asm` несколько мёртвых слов таблиц и текстов, бывших адресами в удалённом коде, заменены нулями (`DEFW 0`, `LD (#0000),A`, `DEFB #ED,#5B,#ED,#5B`).

## 7. Проверки

* `python -I build.py` - все образы с нуля; любое предупреждение sjasmplus - ошибка. (В этой среде процессы Python иногда обрываются без сообщения, код 1, когда на машине работает другой сеанс,
  - тогда просто повторить; `python -I -u build.py` печатает сразу.)
* `tools/check_loader.py` - пересечения загрузчика; `tools/check_reloc.py` - перемещаемость страниц 0 и 5 (раздел 10.3);
* `tools/cmp_ram.py` - ОЗУ в момент старта уровня против образа v0.04 (раздел 10.2); `tools/relocrun.py k` - то же со вставкой в точку k, в эмуляторе;
* эмулятор (`tools/emu`, ZX-M8XXX, harness из ЧВ1): см. README. Снимки - `build/shots`. Ловец падений (`hunt=1`) теперь понимает `I=#BA` (игра), раньше ждал `I=#BE`.

Сделано:

  снимки `build/shots/disk_swap_prompt.png`, `disk_swap_game_started.png`.
* **CALL #0000 в странице 6 / lif.asm.** Отладочная сборка `BR2_DEFS=TRAPS=1 python build.py` (счётчики `HITS`) и ловушки `JR $` в банках ОЗУ
  (`tools/emu/scen/js/trap6.js`: `sp.memory.ram[банк]`) на `#C3F4`, `#C403`, `#C47C` (банк 6, `LOADMM`) и `#ED55` (банк 0, `lif.asm`). Сценарии: демо 2500 кадров, уровень людей 3500, уровень кунгов 3500

## 10. Фаза 2b-4 (загрузка из меню, кунги на коде кунгов, перемещаемая страница 5)

### 10.1 Загрузка слота из стартового меню

* **Причина «Нет записи»** (найдена и исправлена): окно сохранения (`M_M9`) передаёт `SAVgam` номер строки **1..8** (так и в v0.04: `LD A,B / INC A / JP SAVgam`),
  а быстрое сохранение (`qSAVE`) - 0. Слотов было `NSLOTS = 8` (индексы 0..7), стартовое меню переводило клавишу `k` в индекс `k-1`. Поэтому сохранённая в окне
  строка 1 («Игра-001») лежала в слоте 1, а меню читало клавишу `1` как слот 0 (пустой) - сектор с признаком `SAVSIG` был нулевым без ошибки чтения; строка 8
  писалась за концом области слотов (`NSLOTS*SLOTSEC`). Теперь `NSLOTS = 9`: слот 0 - быстрое сохранение, 1..8 - строки окна; в стартовом меню клавиши `1`..`8` -
  «Игра-001..008», клавиша `9` - быстрое сохранение (`menu.asm`, `SLOTMENU`).
* Заодно исправлено: надписи «Номер слота» и «Нет записи» печатались в строке 17 вне окна меню (чёрным по чёрному, не видно) - теперь внутри окна (строки 13 и 14);
  после «Нет записи» игра зависала (`LODgam` возвращается с `DI`, а дальше `HALT`) - `lggBAD` теперь делает `EI` (и при пустом слоте быстрой загрузки из паузы).
* Проверка (эмулятор, `tools/emu/scen/ld_win.txt`, `ld_q.txt`, `ld_ui.txt`): через интерфейс игры - курсор клавишами (`P`/`A`/`O`/`Q`, пробел = огонь): нижняя панель
  (x >= 240, y >= 160) открывает меню паузы; «Сохранить игру» -> строка 1 / строка 8 -> `Y`; `boot` заново -> меню -> `3` -> `1` / `8` - игра восстанавливается (деньги и т.д.);
  «Быстрое сохранение» -> `boot` -> `3` -> `9`; «Быстрая загрузка» из паузы; «Закончить игру» (`toMENU`) -> меню -> `3` -> слот; пустой слот -> «Нет записи» -> меню.
  Снимки: `build/shots/load_*`, `pause_*`.
* Побочные находки при разборе (исправлены): в слоте сохранялись, а в коде читались по **старым адресам страницы 2** (`#BE50..#BF5B`, до переноса переменных уровня в страницу 5)
  процедура звуковых эффектов `pSOUND` (`LD A,(#BF37)`, `LD HL,(#BF30)`, `LD (#BF37),A`), `LD (#BF20),A` в `hrm22+...` (`lib3.asm`), `NOTA`/`NOTA2` (значения `#BF32`), `LD A,(#BF48)` (`END_1`):
  эти обращения шли в массив пуль/зданий. Теперь везде метки (`priv_S`, `NOTA`, `LED+4`, `END_1`). Эффекты AY (`pSOUND`) до этого работали по чужой памяти.

### 10.2 Кунги на коде кунгов

Метод: сборка `work/src_v04/game` двумя способами (`tools/verify_v04.py hum kun`), сравнение образов `br2hum04.N.bin` и `br2kun04.N.bin`, разбор каждого блока `IFDEF KUN`
(они делятся так: чистый сдвиг адресов +2, живое состояние снимка, данные по стороне, настоящие различия кода).

| Вид | Что | Решение |
|---|---|---|
| сдвиг +2 | 604 слова в странице 0, 25 в 4, 134 в 6, 237 в 7, весь код страницы 5 после `_start`: образ кунгов длиннее на одну запись списка `_start` | наша сборка - одна, адреса символьные, различий нет |
| живое состояние | стек, переменные, массивы героев, MONEY/MAZUT/LEVRES, экран, музыкальный модуль (`kun_live.txt`) | не переносится |
| данные по стороне | ландшафт 44SPR/45SPR, кнопки 4K_BUTT/4H_BUTT, карта `4_4.MAP` + `4_4.HER`, `COLOR` #30/#28, `MASTER` 1/0, `fsLAND` 4/5 | файлы уровня и ресурсов (`lev_k`, `land4*`, `butt_k`) - было и раньше |

| деньги `21050` / `21150` | `MONEY` в образе кунгов `00 02 01 01 05 00` | **стартовое значение - 21050 (как у людей)**: образ кунгов снят позже старта (в нём `LEVRES` = `...00 04 7F` вместо `...00 00 7F`: прошло время игры), единственный код, прибавляющий ровно `#100` к `MONEY`, - доставка ресурсов на базу человеческим работником (`ZZ5hum`, `DE=#100`), а `MNYcrc` образа (127) равна контрольной сумме 21150, то есть деньги менялись через `aMONEY/setCRC`; `MAZUT` не менялась. В нашей сборке кунгов за 90 с деньги не менялись (нет доставки). Прямого доказательства «стартовое» в данных автора нет |

Остались различия, не объяснимые данными автора:

Проверка: `python -I tools/cmp_ram.py build/emu/kr.json kun` (сценарий `tools/emu/scen/kun_ram.txt`: остановка в `_start+56`, дамп банков RAM; для людей - `hum_ram.txt`/`hr.json`).

* **Короткие цепочки абсолютных адресов в данных страницы 5** (одиночные слова в таблицах, `DEFB` без «опкода») ищутся только эмулятором (долгие прогоны `tools/emu/scen/soak.txt` с `hunt=1`).
* Переименование остальных `v4_*` (10.4) и дизассемблирование оставшихся куч из образа не сделано.
* Эмулятор-харнесс в этой среде иногда не стартует («harness did not start»), `run_emu.py` повторяет; длинные прогоны (>2 мин) уходят в фон.

## 11. Фаза 2b-5

1. **Портрет после загрузки.** `CONTgm` (io.asm) вызывает `ENTRY2`, а его список начинается с `BUTCLR`, который обнуляет `BUT_H/BUT_N` (портрет и кнопки); пересчёт идёт только по флагу `_event` (`spc_DO`), а после загрузки он 0 - портрет оставался
   пустой заглушкой (выделение `SEL_T/SEL_N` и экран сохраняются правильно). Исправлено: `CALL EVENT` перед `JP ENTRY2`. Проверка (`tools/emu/scen/portrait.txt`: выделение `SEL_T=1, SEL_N=0, _event=1` пока, быстрое сохранение через паузу, быстрая загрузка, boot -> меню 3 -> 9): портрет на месте во всех случаях, `build/shots/portrait_fix_sel_saved_quickload_menuload.png`.
2. **Пустая панель в первых кадрах кунгов** - не ошибка порядка загрузки, а время: панель целиком рисуется первым проходом игрового цикла, а до него идёт инициализация. У людей панель пуста 2 кадра, у кунгов 4: лишние 2 кадра = `FOGALL` (SET 7 для 3844 клеток, около 130 тыс. тактов) - она есть в оригинале v0.04 кунгов
