# Утилиты автора на Python и правка ресурсов

Утилиты автора (`archive/unz/BR2_DEMO/CPP/*.CPP`, Turbo C, BGI) портированы на Python: `tools/gfx/` (графика), `tools/txt/` (тексты).
Исходники в архиве только читаются; результат по умолчанию пишется в `build/author_out/`. Запуск: `python -I tools/gfx/land.py [--images DIR] [--out DIR]`.
Проверка всех портов на данных архива и круга ресурсов: `python -I tools/check_assets.py` (`--trd` - ещё и сборка двумя способами, минуты).

Не портированы (в исходниках остаются как есть): **4DISK1/2, 4FORMAT1/2** - работа с диском и форматирование, заменены слоем TRD (`tools/trd.py`, `build.py`);
**4CHECKER, 4CRCEXE** - защита (проверка и контрольные суммы), в сборке не нужна; **4TRACE_X** - отладка (трассировка).

Не из списка, но выведено сверкой с архивом: `6144.EXE` (TIF -> экран Спектрума для 4INSTR0, 4INTRO, MAINFRAM; исходника нет) - `tools/gfx/scr.py: tif_to_scr6144`; упаковщика LPZ в архиве
нет (`tools/lpz.py` пакует иначе: поток не совпадает байт-в-байт, 0 из 66 файлов), поэтому LPZ хранятся с исходным потоком (ниже).

Расхождений порта с архивом нет. Различия assets/ с архивом: 53 файла `assets/data` совпадают с `DATA` архива; блоки `assets/hum` (v0.04) новее и в архиве входов не имеют.

## Ресурсы: `assets_src/` и сборка

Редактируемые исходники лежат в `assets_src/`, из них `tools/assets.py import` делает двоичные ресурсы (`build/assets/`, 129 файлов: всё, что читает сборка (122), и 7 героев архива), и `build.py` берёт INCBIN и файлы оттуда.
**Выбор: сборка всегда идёт из `assets_src/`** (один источник правды, нельзя забыть пересобрать): `python -I build.py`. Прежний способ - `python -I build.py --bin-assets` (или `BR2_BIN_ASSETS=1`): берёт двоичные `assets/`.
TRD обоих способов одинаковы побайтно (`check_assets.py --trd`).

### Как править

* **Спрайт или тайл.** Откройте PNG в любом редакторе (1 бит: чёрный = точка, белый = фон; режим не менять; можно RGB - тёмное считается точкой). Не выходите за ячейки автора:
  тайлы 16x16, кадры героев 16x16 / 16x24 / 24x24 в порядке автора (см. `tools/gfx/hero.py`, типы 2..9, S; у маски 1 = закрашено). Затем `python -I build.py`.
* **Текст.** Правьте `text/*.txt` в UTF-8. Строки титров/заданий центруются сами; до 12 знаков в строке титров, 20 / 32 знака в строках заданий; допустимы только знаки шрифта (таблица в `tools/txt/common.py`;
  знак без однозначного символа записан как `{NN}`). В инструкции словарь пар пересчитывается инструментом автора заново; размер `4instr.dat` может измениться - проверьте, что влезает в страницу.
* **Цветная картинка (`gfx/pictures/4title.png` и др.).** Палитра 16 цветов (индекс = цвет + 8 * яркость); в клетке 8x8 не более двух цветов одной яркости (иначе ошибка с координатами).
  Нетронутые клетки берутся из исходного файла дословно (в том числе flash).
* **LPZ-картинки и ролики.** Пока картинка не изменена, в сборку идёт исходный поток `.lpz` дословно. Изменённая упаковывается `tools/lpz.py`: поток другой по байтам и может быть другой длины (сборка проверяет размер).
* **Карты.** `maps/*.csv` - 64 строки по 64 клетки (номер тайла/объекта), расстановка - по записи на строке.
* Пересоздать `assets_src/` из `assets/`: `python -I tools/assets.py export` (затирает правки!). Список соответствий: `python -I tools/assets.py list`.

Что **не редактируется** пока (11 файлов, копируются как есть из `assets_src/raw/`): музыка (`music/*`, 6 файлов), `start1/LP2..LP4` (упакованные страницы интро), `hum/1_r2_FEE2.bin`
(286 байт, назначение не установлено), `hum/6_junk_EBC9.bin` (мусор). Геометрия кадров у `3_r0_D270/D870/F770`, `4_r0_DA40`, `hrm18` неизвестна: их листы - просто столбцы (см. `assets/hum/FORMATS.md`).
Файлы `assets/`, которые сборка не читает (22), в `assets_src/` не вынесены, кроме 7 героев (`4kapell, 4king, 4tank_tr, 4varlok, 4zenit, 4zerg, 4~shadow`: они нужны для проверки порта 4HERO):
`4names.dat`, `4misc2x2/3x3.dat`, `data/4instr*.dat` (версия архива; игра берёт v0.04 из `start1/data`), карты `4_10`, `4_100`, `kun/*`, `hum/M_r3482_5B3A.bin`, `hum/datSCR.bin`.

## Форматы

Подробности и разбор блоков v0.04 - `assets/hum/FORMATS.md`. Кратко: листы автора 256x192 (TIF, 194 байта заголовка, чёрный = 0; конвертеры делают `^0xFF`);
спрайт с маской - пары байт `(M, M^I)` столбцами; кнопки 24x24 (3 байта x 22 строки, без верхней и нижней строк ячейки); тайл 16x16 = 2 столбца по 16 байт; названия 6x7 байт;
шрифт 4FONT.FNT - 114 знаков 8x8; ч/б картинки LPZ - 6144 байта в экранной раскладке Спектрума, цветные - SCR 6912; TV16 - кадр 28x36, 2 точки в байте (старшая тетрада слева), 504 байта, 32 кадра на ролик.
